# Per-request attribute overhead in model_engine gen-batch prep loop

> Part of the [Scheduler & executor regression cookbook](index.md) · schema: [case-template](../case-template.md)

- **Provenance:** nvbug `6376948` · commit `d9ca6f1c3e84` · PR #15750 —
  "[fix] Reduce per-request attribute overhead in model_engine hot path".
- **Symptom:** `mean_gen_worker_per_iter_device_step_time` regressed
  8.384 → 8.691 (lower-is-better) on the gpt-oss-120b gen-only workload;
  after the fix: 7.869. Numbers from the PR description, which also notes the
  fix was generated by repair-bot.
- **Root cause:** the generation-batch preparation loop in
  `PyTorchModelEngine` (`tensorrt_llm/_torch/pyexecutor/model_engine.py`)
  did repeated per-request `LOAD_ATTR` lookups on `self.use_mrope` and
  `request.py_multimodal_data`/`py_batch_idx`, and unconditionally called
  `_pad_batch_seed_mrope_delta_cache` (Python frame setup) even for
  non-mrope models. Under high concurrency this pure-host cost accumulated
  per iteration for a model that uses neither mrope nor multimodal data.
- **How introduced:** the causing commit is not named in the PR. The
  mechanism points at mrope / multimodal support branches sitting inside the
  generic per-request generation loop, taxing models that never use those
  features.
- **Fix mechanism:** hoist `self.use_mrope` to a function-scope local
  (`_use_mrope`, `LOAD_FAST` instead of `LOAD_ATTR`), add a batch-level
  `_has_any_multimodal_request` short-circuit so non-multimodal batches skip
  the per-request `py_multimodal_data`/`py_batch_idx` loads, and gate the
  `_pad_batch_seed_mrope_delta_cache` call on `self.use_mrope` at the call
  site. Semantics-preserving host-side micro-optimizations only.
- **Detection signal:** per-iteration gen-worker step time creeps up with no
  GPU-kernel change; a Python profile of the forward-step prep path
  (`forward` -> `_prepare_inputs`/`_prepare_tp_inputs`) shows attribute
  loads and no-op feature calls scaling with batch size. Check the fix is
  present with `grep -n "_has_any_multimodal_request"
  tensorrt_llm/_torch/pyexecutor/model_engine.py`; compare host span per
  iteration across builds with `perf-host-analysis` on an nsys trace.
- **Prevention/guard:** no regression guard was added by the PR; the gap is a host-time microbenchmark for the
  gen-batch prep loop at high request count, plus a review checklist item:
  no per-request `self.*` attribute lookups or unconditional feature-path
  calls inside the per-request loop — hoist invariants and short-circuit
  disabled features at batch level.
- **Generalizes to:** pattern-host-work-on-hot-path — feature-support
  branches (mrope, multimodal, spec-decode, LoRA) paying per-request Python
  cost in the generic loop even when disabled; carries to any O(batch)
  executor loop where invariant `self.`/`getattr` lookups or no-op helper
  calls multiply under high concurrency, to sampler per-request prep, and to
  KV-cache/slot bookkeeping loops in the pyexecutor.
