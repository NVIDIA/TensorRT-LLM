# VDN MiniMax-H3

VDN reuses MiniMax-H3's packed transformer, conditioning, token refiner,
modulation, feed-forward layers, VAEs, schedules and output handling. Trunk
attention is replaced, and trunk pointwise operations are fused. The projections and dense attention calls continue to use
TRT-LLM modules. The linear branch implements the released frame-wise joint
solve; token-wise DeltaNet kernels do not implement this recurrence.

The implementation follows [OpenVDN/vdn-minimax-h3](https://github.com/OpenVDN/vdn-minimax-h3)
(commit `e262cb5770b3dc992d4f44f251cd17bbfe0c4d8b`). The upstream class identifier
is `VDNMiniMaxH3Transformer3DModel`. No upstream Python code is executed when
loading a checkpoint.

## Loading and execution

Use `examples/visual_gen/models/vdn_minimax_h3.py` for the public API. The registry
contains the checkpoint ID and pipeline defaults. An existing H3 checkpoint can
be supplied through `pipeline_config.base_checkpoint` to reuse its weights and
text encoder. Otherwise the backbone is read from the VDN repository's `h3-base`
directory and its omitted text components are resolved from MiniMax-H3.

The overlay's LoRA pairs are merged in order into BF16 backbone weights before
TRT-LLM fuses QKV and gated-MLP projections. Missing pairs, incompatible shapes,
unknown branch keys and missing model parameters fail loading. The stage selects
the released eight-step or fifty-step overlay, including its attention geometry.

This initial implementation supports BF16 on one GPU. Quantization and sequence
parallelism are rejected. FA4 window attention batches disjoint query groups in
one variable-length call, with a shared SDPA call for global rows. Both
anchor frames remain dense, while only interior frames enter the convolution and
recurrence. Cached layout belongs to one request, like H3's cached text and RoPE.

## Validation

`tests/unittest/_torch/visual_gen/test_vdn_h3.py` checks the window against a dense
boolean mask, the separable convolution against Conv3D, and the bidirectional
recurrence against direct linear solves. It also checks meta-device construction,
conditioning-row layout and LoRA validation. The public API example has a B200
integration smoke test in `test_vdn_h3_e2e.py`; set `LLM_MODELS_ROOT`, or override
its VDN/H3 locations with `VDN_H3_CHECKPOINT` and `MINIMAX_H3_CHECKPOINT`.

The decoded-media quality test consumes `validation/prompt.pt` and
`validation/reference.pt` under the VDN checkpoint (override with
`VDN_H3_VALIDATION_DIR`). Provision these alongside the checkpoint in CI;
missing fixtures are errors. The prompt is upstream `prompts/example_0.pt`.
The golden is generated by the pinned upstream repository's own
`build_inference_model`, `generate_latents` and `decode_and_save` functions, with
inference kernels enabled and the decomposed softmax backend. It shares neither
the TRT-LLM sampler nor its decoders. Use seed 0, a CUDA generator, 1344x768,
124 frames and eight model evaluations (nine sigma points). Save uncompressed
`video` (uint8 BTHWC) and `audio` (float32 BCT) CPU tensors. Inspect the reference
clip before accepting it: example_0 depicts an animated swordswoman amid smoke
and red sword trails. The 128x128 diagnostic canvas does not produce meaningful
video and must not be used as a quality baseline.

Acceptance requires mean AlexNet LPIPS below 0.15 over all frames and audio
relative L2 below 0.1. Shape, finiteness and non-black checks are only smoke tests.
A numerical match against a visually invalid golden does not establish quality.

## Inference kernels

Window queries with identical bounds share one gathered KV window. The temporal
five-tap stencil, SiLU and L2 normalization run in one frame-tiled Triton kernel;
spatial convolution continues to use PyTorch's channels-last depthwise Conv2D.
QK normalization and partial RoPE compile together using the existing H3 rotary
function. These pointwise kernels retain FP32 intermediates, matching upstream's
inference arithmetic rather than rounding each eager intermediate to BF16.
The bidirectional state recurrence remains FP32 and uses batched multiply-add;
window-boundary state reads and alpha bridging are vectorized. Frame statistics
use TF32 for the FP32 key Gram matrix, matching upstream inference, while the
state solves remain FP32. The TF32 setting is scoped to that matrix product.
The text refiner continues to use the existing H3 implementation.

Benchmark the same BF16 checkpoint, prompt cache, resolution, frame count, seed,
GPU and eight evaluations against upstream's tuned BF16 configuration. Exclude
checkpoint loading and initial kernel compilation, report denoising separately
from decoding/encoding, and recheck quality after optimizations. Report the
precision and actual workload with timings; these numbers do not establish FP8
or multi-GPU performance.
