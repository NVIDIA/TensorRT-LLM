### The new schema surface

```yaml
environment:
  kind: local
  python: /path/to/TensorRT-LLM/.venv-3.12/bin/python
  env:
    TRTLLM_MODELING_V2: require
    TMPDIR: /path/to/scratch/tmp
    CLAUDE_CODE_TMPDIR: /path/to/scratch/tmp

  # A checkpoint the STOCK modeling path already supports. Optional.
  substrate_checkpoint: /path/to/Qwen3-30B-A3B
```

Optional, validated to exist when set. The must-exist check is not decoration:
the proxy is reached for **only after** the run's own checkpoint has already
failed, which is the longest step in preflight, so a missing proxy turns one
failure into two with a wait in between.

### The discriminator, and where it comes from

```python
UNSUPPORTED_ARCHITECTURE_MARKERS = (
    "Unknown architecture for AutoModelForCausalLM",
    "Unknown architecture for AutoModelForMultimodalEncoder",
    "is not supported in TRT-LLM yet",
)
```

Both registries that can answer "I have never heard of this architecture" are
keyed on the checkpoint's own `architectures[0]`, which is exactly the string
this workflow exists to introduce:

- `tensorrt_llm/_torch/models/modeling_auto.py` — `AutoModelForCausalLM.from_config`
  raises `ValueError(f"Unknown architecture for AutoModelForCausalLM: ...")` when
  `_resolve_class` comes back `None`, and its multimodal-encoder branch raises the
  same sentence with `AutoModelForMultimodalEncoder` in it. `_resolve_class`
  returns `None` because `get_registered_model_class`
  (`tensorrt_llm/_torch/models/modeling_utils.py`) resolves the lazy built-in
  provider and then misses in `MODEL_CLASS_MAPPING`.
- `tensorrt_llm/models/automodel.py` — `AutoConfig.from_hugging_face` and
  `AutoModelForCausalLM.get_trtllm_model_class` raise
  `NotImplementedError(f"The given huggingface model architecture {hf_arch} is not
  supported in TRT-LLM yet")` when `MODEL_MAP.get` returns `None`.

Matched on **text** rather than on an exception type because the gate runs the
engine as a subprocess and reads a log: there is no object to catch. Each marker
is the invariant half of its message — the architecture name is interpolated in
and varies per run. The constant carries a comment naming both raise sites.

`test_a_real_host_failure_is_never_answered_by_measuring_another_model` is the
test that holds the line: it declares a proxy, fails the first boot with
`Impossible to fit in any sequence in kvCache`, and asserts the runner was
called **once**. Widening the fallback to "any failure" would answer a real
kvCache fault on the target by silently booting a different model and reporting
green.

### What is recorded when the fallback fires

```
notes:
  - substrate proven on `/proxy-ckpt`; this checkpoint's own geometry is
    unverified, so a kvCache sizing fault will surface at the first boot gate
    rather than here.
```

Verbatim from the finding, and asserted verbatim by a test. A note that said
only "substrate gate passed" would be read later as the claim the unqualified
gate makes, and the difference between the two is precisely which failure this
run has been protected from. `MPI_ERR_SPAWN` and NVRTC's missing `cuda.h` still
are; kvCache sizing no longer is.

When the architecture is unknown and no proxy is declared, the error names the
fix rather than the architecture:

```
substrate gate: the stock modeling path does not know this checkpoint's
architecture, which is the normal state of affairs for a model this workflow
is onboarding — it is not a fault in the checkpoint or the host. ...
Declare `environment.substrate_checkpoint`: ...
Do not reach for `--skip-substrate-gate` — that also gives up the MPI spawn and
NVRTC checks, which do not depend on the checkpoint at all.
```

### The polarity, deliberately not asserted

`01-architecture/` establishes that in this checkpoint's `hybrid_layer_pattern`,
`1` is sliding-window and `0` is full attention — 39 against 9 of 48. The probe
does **not** encode that. Nothing in `config.json` states it, the next
checkpoint may invert it, and a survey that guessed would silently window the
wrong 39 layers. So the demand reports the counts factually, keyed by the raw
value (``39 of `1`, 9 of `0```), and ends with "which value means which kind of
attention is the config's own convention and is a question for the plan phase".
`test_the_survey_reports_the_pattern_and_refuses_to_interpret_it` asserts both
the sentence and the absence of any polarity claim.

## F004 — an embargo that can name an out-of-repo tree

### Files changed

| file | why |
|---|---|
| `agent-flow/agent_flow/workflows/staircase_onboard/task_schema.py` | `_validate_source_embargo` accepts an absolute path that resolves outside `trtllm_repo_path` (must-exist kept), still rejects one that resolves inside with a message naming the fix, and its docstring states that a directory entry embargoes the tree beneath it |

| `agent-flow/tests/workflows/staircase_onboard/test_runtime_and_scope.py` | 6 new tests — out-of-repo accepted, in-repo absolute rejected, out-of-repo missing rejected, and three on the rendered block (out-of-repo only, both kinds, the directory sentence) |

### The rule, and the discriminator in the prompt

Validation splits on `Path(entry).resolve()` against `Path(repo).resolve()`.
The rendered block splits on `p.startswith("/")` — which is not a heuristic,
because validation has already guaranteed that an absolute entry resolves
outside the repo. No new parameter was threaded through `prompts/__init__.py`.

```
## Embargoed sources

This checkpoint already has an implementation in this repository. This
checkpoint is implemented in another engine's checkout on this filesystem,
outside this repository. For this run it is **off limits to read**:

- `tensorrt_llm/_torch/models/modeling_qwen3_5.py`
- `/lustre/<fs>/portfolios/<org>/users/<user>/vllm`

An entry that names a directory embargoes the whole tree beneath it, not just
the directory itself.
...
**Running the in-repository implementation is expected.** Under
`TRTLLM_MODELING_V2=off` the engine uses exactly that implementation, ...

**Running the out-of-repository engine as a black-box oracle is expected;
reading it is not.** Start its server, send it the workload and measure
against what it returns — that is why the checkout is named here rather than
merely avoided. What it must never be is a file you open.
```

A run with only in-repo entries renders byte-for-byte what it rendered before,
apart from the directory sentence.

## What the findings did not anticipate

1. **`runtime_index.yaml` is a hard dependency of a new probe, not a
   follow-up.** `test_survey_probes.py::test_every_demand_a_runtime_area_declares_is_one_some_probe_can_produce`
   asserts in both directions: an area may only claim demands the survey can
   emit, **and** a probe may only emit demands some area claims. So
   `attention.hybrid` and `attention.sink` could not land without the index
   entry, which is the invariant working exactly as written — a demand no area
   claims is a checkpoint feature that maps to no engine knowledge at all. It
   also forced a real decision rather than a rubber stamp: `attention.hybrid`
   is claimed by **two** areas, because differing per-kind KV head counts are a
   question for the cache manager as much as for the attention backend.

2. **The prefix list cannot reach the sink keys, and the finding's proposed
   prefixes do not cover `hybrid_layer_pattern` either.** `swa_`, `local_` and
   `full_attention_` clear the five `swa_*` geometry overrides, but
   `add_swa_attention_sink_bias` has the layer kind in the *middle* of the name
   and `hybrid_layer_pattern` matches none of the three. Adding `add_` as a
   prefix would claim every `add_*` key in every config. Introduced
   `_CLAIMED_SUBSTRINGS = ("attention_sink", "layer_pattern")` — two entries,
   both being exactly what the new probes glob on, so the claim and the probe
   cannot drift.

3. **Naive period detection reports a period that occurs once.** The first
   implementation said the 48-entry pattern repeated "every 47 layers", because
   `values[47] == values[47 % 47]` happens to hold when the last entry equals
   the first. Candidates now stop at half the length. Kept as its own test,
   because a stack whose global layers land every sixth position and a stack
   whose first block is short are genuinely different stacks and the survey is
   the only thing that says which this is.

4. **`attention_chunk_size` was left in `unrecognized` on purpose.** F003's
   table pairs it with `hybrid_layer_pattern`, but it is a window *length*
   rather than a per-layer structure, `attention.windowing` already reports
   `sliding_window=128`, and the `sparse_attention` area's own summary calls it
   out by name. Claiming it would have meant widening the windowing probe,
   which no finding asked for. Flagging it here rather than doing it silently.

5. **`--skip-substrate-gate`'s help was part of F001's surface.** The finding
   correctly reads that flag as the wrong shape for this problem; its help text
   still recommended it as the escape hatch of last resort with no mention of
   the new one. One sentence added, so the operator who hits the architecture
   error and reaches for `--help` is pointed at `substrate_checkpoint` instead.

6. **The F002 tree was untouched.** `members_for`, the member-set gate loop and
   the witness member all pass through `substrate_gate` and `source_embargo`
   unchanged — the substrate gate runs before any member is resolved (it is a
   host claim, not a topology one) and the embargo is rendered per role, not
   per member. Nothing in this change needed to know about the member set.
