## Part 3 — which option was taken

**Option (a): `PATH` is composed, not replaced.** The resolved prefix now ends
`...:/usr/bin:/bin:"$PATH"`, so a spec that pins its own interpreter ahead of
everything else no longer deletes the container's MPI, CUDA and system tool
directories as a side effect.

This was the right half of the choice. Option (b) — rejecting a `PATH` that
does not end in `:$PATH` — would have taught every task author a rule in order
to prevent a mistake the code can simply not make. The failure it prevents is
worth recalling: the spec line looked entirely reasonable, and its consequence
was `mpirun: command not found` several layers away, inside a probe whose
output was then silently discarded.

The `67` rather than `61` is not a discrepancy: the earlier figure came from a

- the probe payload, run single-process through the compute session:
  `trtllm_ops: 277`, `catalog: 76` (61 passed / 2 failed / 13 absent),
  `modules: 265`, `error: ""`, rc=0;
- the same payload under the old multi-rank launch: **rc=127**, no payload,
  `mpirun: command not found`;
- the orchestrator's own `--dry-run`, which now prints the real counts.

## What the finding did not anticipate

**The runtime index is a hard prerequisite, not a follow-up.** The two new
survey demands had to be registered in `runtime_index.yaml` in the same
change, or an existing drift-guard test fails. A probe that reports a demand
the index does not know about is treated as drift, which is the correct
behaviour and was not obvious from the finding.

**`attention_chunk_size` was deliberately left unclaimed.** It is still in the
unrecognized list. For this checkpoint it is a red herring — the reference
implementation never reads it, and the real windowing comes from
`sliding_window` — so widening the windowing probe to claim it would have
recorded a fact that is not true of this model. Flagged rather than absorbed.
